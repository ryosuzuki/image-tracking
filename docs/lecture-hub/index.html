Suggested class flow · 80 minutes

  1. Why augment paper? · 10 min. DigitalDesk, MagicBook, Tangible Bits: connect physical representations to digital behavior. Projection is not automatically image tracking.
  2. How do we find the target? · 20 min. Compare square fiducials, colored dots, and natural-image features. Explain identity vs geometry, homography vs metric pose, camera calibration, and coordinate transforms.
  3. What can designers build? · 15 min. Paper animation, data visualization, physical authoring and Dynamicland. Ask which input each system actually senses.
  4. Live demo + failure analysis · 15 min. Start with a printed marker and simple 3D content; demonstrate loss, reacquisition and ambiguity only after physical acceptance.
  5. Capture → remix lab · 20 min. Inspect a permitted recorded take, modify content in replay, then return to the headset for validation. Replay success does not prove live registration.

Timing is a proposal, not a scheduled class commitment. Slide-template work comes after media review.

Review package · Delivered

Lecture sources + readiness map

Media previews, project/paper/video links, uncertain references labeled, current-source audit and this plan available for review.

M1 · First vertical slice

One printed marker → one 3D object

Quest native app, fixed target dimensions and known calibration. Record physical motion, occlusion/reacquisition, ID and pose confidence, and binocular alignment. A synthetic test alone cannot pass.

M2 · Controlled comparison

Calibrated dots versus ArUco

A4/Letter targets with measured dimensions and distinct IDs. Compare recognition, wrong IDs, latency and physical registration under matched light, distance and motion.

M3 · Lesson catalog

Expand a proven shell

Molecule/card, cube-net/animation and multi-target composition behind common UI, one scene mapping per card. Add natural-image metric AR only after its own physical gate.

M4 / M5 · Replay → prototype

Remix in Three.js, then return to Quest

Replay pause/scrub/target overlay, user-authored content mapping and a verifiable round-trip. Unity import follows only when the coordinate and temporal contract is stable.

M6 · Classroom release

Package a repeatable teaching session

Clean install, printed-pack measurement, offline/failure behavior, reset path and two reproducible runs. Record which demos pass; keep unaccepted ones out of the required live lesson.

Recommended next action: M0 reconcile installed/source baseline, then M1 physical acceptance before adding more content. Existing capture-recorder modification was previously stopped; this plan reuses documented outputs without changing that app.
